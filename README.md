# 青藤图书室 · 校园图书借阅预约系统

面向小型图书室（班级、系部、社区）的借阅管理系统。**纯静态前端**：不需要服务器、不需要数据库，所有数据存在浏览器 `localStorage` 里，可以直接扔到 GitHub Pages / 任意静态托管上跑。

<https://gedongyou.github.io/qingteng-library/>

## 功能

**读者端**
- 馆藏检索：按书名 / 作者 / ISBN / 标签 / 分类查，可按「在架可借」筛选、按上架时间或借阅热度排序
- 图书详情：库存实时、每册副本的条码与状态（在架 / 借出 / 已预留 / 遗失 / 修补）
- 预约排队：书全部借出时可预约，归还后系统按队号自动把书锁定给下一位，保留 3 天
- 我的书房：在借（含逾期高亮）、借阅历史、预约进度、改密码
- 借阅规则：借期 30 天、最多同时 5 册、可续借 2 次每次 15 天、逾期 0.2 元/天
- 五心主题书架：64 种书按「红心铸魂 / 仁心修身 / 恒心砺学 / 匠心强技 / 创心赋能」分成五架，首页五个入口，检索页顶部可切架
- 数字看板 `board.html`：六项主指标、分类分布、五架构成、十四天借还曲线、借阅排行、借阅规则同屏，适合挂在走廊屏上

**管理后台**
- 仪表盘：今日借出/归还、当前外借、逾期未还、预约待处理、14 天借还趋势、分类馆藏分布、借阅排行、最近操作
- 借还办理：刷借书证 / 条码自动识别，一次完成借出或归还，逾期自动算罚金
- 借阅记录：全量流水，可按状态筛选、标记归还
- 预约管理：排队视图、手动置为「已到书」、办理借出、取消
- 图书管理：书目 + 副本两级维护，增删副本、改单册状态（遗失 / 修补）
- 分类管理：中图法 15 个大类
- 读者管理：借书证、冻结 / 解冻、借阅上限、重置密码
- 公告管理、系统设置（站点信息 + 全部借阅规则）、操作日志
- 导出：图书台账 / 读者名册 / 借阅流水 CSV

## 本地运行

任选一种：

```bash
# 1) 自带的小服务器（零依赖，需要 Node >= 18）
node serve.mjs 8092

# 2) 或者直接用 Python
python3 -m http.server 8092
```

然后打开 <http://127.0.0.1:8092/>。

> 直接双击 `index.html` 用 `file://` 打开不行——ES Module 和 `localStorage` 都需要 http(s) 协议。

## 数据说明

- 首次打开自动写入种子数据：64 种图书、152 册副本、7 个用户、24 条借阅、5 条预约、3 条公告。
- 数据存在浏览器本地，**换浏览器或清缓存就回到初始状态**。
- 后台「系统设置 → 数据」里可以一键重置演示数据。
- 密码用 SHA-256(salt + 明文) 存储（`assets/js/sha256.js` 内置纯 JS 实现，http 局域网访问也能用；https 下自动走 `crypto.subtle`）。

## 架构

原来这套系统是 Node + SQLite 的后端版。改成纯静态时保留了全部页面代码，只把最底层的 `api()` 从 `fetch` 换成调用本地的 `dispatch()`：

```
页面脚本 → common.js api() → api-local.js dispatch() → store.js 业务 → db.js localStorage
```

接口路径、参数、返回结构和提示文案与原来的 REST 接口完全一致，所以页面层几乎零改动。

## 部署到 GitHub Pages

```bash
git init
git add .
git commit -m "青藤图书室：纯静态版"
git branch -M main
git remote add origin https://github.com/<用户名>/<仓库名>.git
git push -u origin main
```

然后在仓库 **Settings → Pages** 里把 Source 选成 `Deploy from a branch`、分支 `main`、目录 `/ (root)`，保存后等一两分钟即可。

`.nojekyll` 已经加好了，避免 Jekyll 处理 `assets/` 里的文件。

## 两种部署形态

| | 单机演示版（本仓库） | 共享部署版 |
|---|---|---|
| 形态 | 纯静态，HTML + CSS + ES Module | Node 20+ 内置 `http` + `node:sqlite` |
| 数据 | 浏览器 `localStorage`，一部机器一份 | 一份 SQLite 文件，多人共用 |
| 部署 | 丢进静态托管即可，零运维 | 一条命令启动，局域网内可访问 |
| 适用 | 单台电脑、走廊屏、答辩现场演示 | 系部图书室日常借还，多人同时操作 |

两版共用同一套页面与业务规则，接口路径、参数和返回结构完全一致，差别只在最底下的数据层。共享部署版在 `library/` 目录（未包含在本仓库），细节见站内 `about.html`。

## 已知限制

纯静态意味着数据只在本机浏览器里，不能多人共享同一份库存。两个人同时操作会互相覆盖，换设备看不到之前的记录。需要「馆员改了、读者那边立刻看到」时，用上面的共享部署版。
